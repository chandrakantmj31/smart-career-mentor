# Smart Career Mentor

AI-assisted career guidance for students and freshers: take an assessment, get explainable career matches, analyze your resume, see your skill gaps and follow a 4-stage learning roadmap.

> **How the "AI" works:** all scoring (career match, resume score, skill gaps, roadmap) is rule-based and fully explainable. Nothing is sent to a third-party AI provider, and results are deterministic. The resume score is an **estimate**, not an official ATS score; real ATS products differ.

## Features
Register / login (secure cookie session), forgot & reset password, optional Google sign-in · career assessment · career recommendations with a visible score breakdown · PDF/DOCX resume analyzer · skill gap analysis with saved progress · roadmap with task tracking · live dashboard · profile page.

## Tech stack
Flask (REST API) · MongoDB Atlas via PyMongo · Tailwind-styled HTML pages from Google Stitch + vanilla JS · Gunicorn · Render.

## Folder structure
```
backend/            Flask API (app/routes, app/services, app/data, tests, run.py, .env.example)
frontend/           The pages (login, register, dashboard, assessment, ...) + assets/
stitch_source/      Your original, untouched Stitch export
tools/              build_pages.py / build_auth.py regenerate pages from stitch_source; e2e scripts
render.yaml         Render deployment blueprint
```
Flask serves the `frontend/` pages itself, so one deployed URL runs the whole app (no CORS or cross-site cookie problems).

## Run locally
1. Install Python 3.12+. In a terminal:
   ```
   cd backend
   python -m venv .venv
   .venv\Scripts\activate          # Windows   (macOS/Linux: source .venv/bin/activate)
   pip install -r requirements.txt
   copy .env.example .env          # macOS/Linux: cp .env.example .env
   ```
2. **MongoDB Atlas:** create a free cluster → *Database Access*: add a user + password → *Network Access*: allow your IP (use `0.0.0.0/0` for Render) → *Connect → Drivers*: copy the connection string into `MONGODB_URI` in `.env` (replace `<password>`).
3. Set `FLASK_SECRET_KEY` and `JWT_SECRET_KEY` in `.env` to long random strings (`python -c "import secrets;print(secrets.token_hex(32))"`).
4. `python run.py` → open http://localhost:5000

## Google sign-in (optional)
Google Cloud Console → *APIs & Services → Credentials → Create OAuth client ID (Web)*. Add the authorized redirect URI `http://localhost:5000/api/auth/google/callback` (and your Render URL version). Put the client ID/secret/redirect URI in `.env`. Until all three are set, the "Continue with Google" button stays disabled. Only identity scopes (`openid email profile`) are requested.

## Tests
```
cd backend
pip install -r requirements-dev.txt
pytest
```
Tests use an in-memory Mongo (mongomock), so they need no database or internet.

## API (all JSON; writes need the `X-CSRF-Token` header, which the frontend sends automatically)
| Area | Endpoints |
|---|---|
| Auth | `POST /api/auth/register · login · logout · forgot-password · reset-password`, `GET /api/auth/me`, `GET /api/auth/google/{config,start,callback}` |
| User | `GET/PUT /api/users/profile` |
| Assessment | `POST/GET /api/assessment`, `GET /api/assessment/results` |
| Careers | `GET /api/careers/recommendations`, `GET /api/careers/available` |
| Resume | `POST /api/resume/upload` (multipart field `resume`; analyzes immediately), `POST /api/resume/analyze`, `GET /api/resume/history`, `GET /api/resume/<id>` |
| Skills | `GET /api/skills/gap-analysis[?career_id=]`, `PUT /api/skills/progress` |
| Roadmap | `POST /api/roadmap/generate`, `GET /api/roadmap`, `PUT /api/roadmap/progress` |
| Other | `GET /api/dashboard`, `GET /api/resources`, `GET /api/health` |

## Deploy on Render
1. Push this repo to GitHub (`.env` is git-ignored).
2. Render → *New → Blueprint* → pick the repo (it reads `render.yaml`). Or *New → Web Service* with build `pip install -r backend/requirements.txt` and start `cd backend && gunicorn run:app --bind 0.0.0.0:$PORT --workers 1 --threads 4`.
3. In the service's **Environment** tab set `MONGODB_URI`, and `FRONTEND_URL` to your `https://<name>.onrender.com` URL (secrets are auto-generated by the blueprint). Optional: the three `GOOGLE_*` values.
4. In Atlas *Network Access*, allow `0.0.0.0/0` (Render's free tier has no fixed IP).
5. Open `https://<name>.onrender.com/api/health` → `{"status":"ok"}`, then register an account.

## Known limitations
* **Password-reset emails are not sent** yet (no email provider configured). In development the link is written to the server log; production needs an email service added to `forgot_password`.
* **Job recommendations** (`job_recommendations` collection) are not implemented: a real jobs feed needs an external provider/API key.
* Resume files are not stored; only extracted text is kept, privately, per user.
* Rate limiting uses in-memory storage (one worker). For several workers/instances use Redis.
* Render's free tier sleeps when idle, so the first request after a pause is slow.
